# ja-naming — 用語選定と指示対象の固定

コード識別子、API 名、既存 UI の固定ラベルには適用しない。

規則の本体は `ja-writing-rules` スキルの `reference/naming.md` にある。ここには書かない。

- 名前より先に対象を固める
- 既存の定着語を優先する。無ければ造語せず文で書き下す
- 直訳のカタカナ語・混成語を作らない
- 中黒でつないだ語を見出しや呼び名に使わない

同一対象を一語で貫くこと、送付済みの語を黙って言い換えないことは、`ja-writing-rules` の SKILL.md「語をそろえる」「決まった語を動かさない」が決める。

## 具体例 (Before / After)

### 直訳・混成語の回避
- **Bad**: バウンデッドなエンベロープ形式でのリザルト返却
- **Good**: サイズ上限付きの結果 (bounded envelope) を返す

### 安易な造語の回避
- **Bad**: 合格域と不合格域の中間にある領域を「保留帯」と命名する
- **Good**: 合格閾値と不合格閾値の間にある領域 (命名せず文で説明する)

### 中黒連結の解消
- **Bad**: 検証・退避ゲート
- **Good**: 検証に失敗したデータを退避する処理
