# 主張と根拠のつながりを確かめる

設計文書、研究の記録、論文の草稿に適用する。新しく書くときにも、人の文書を直すときにも使う。直すときに論証の欠けを見つけたら、自分で補わずに書き手に伝える ([revising.md](revising.md))。

文が読みやすくても、主張が根拠より広ければ読み手は誤る。研究や設計の文書で読み手がまず確かめるのは、この点である。

## 因果には仕組みを添える

「A によって B が起きた」と書くなら、A がどう B を起こすのかを一文で添える。仕組みを書けないなら、因果ではなく同時に起きたことを書いている。そのときは「A の後に B が起きた」と書き、因果は推測として分ける。

## 例が支える範囲に主張を狭める

一つの例や一つの条件での結果から、一般の主張を書かない。主張は、例と条件が支える範囲にとどめる。範囲を超えて書きたいなら、何を確かめれば広げられるかを添える。

## 別々のものを一つにまとめない

性質の違う二つのものを「同じ」「ともに」と一語でくくらない。結果の原因を一つにまとめるときは、ほかの原因を退けた根拠を書く。

## 譲歩のあとは論を進める

「ただし」「とはいえ」で反対の事情を認めたら、その事情を踏まえて論を一段進める。認めただけで元の主張に戻ると、反対の事情がなぜ主張を崩さないのかが書かれないまま残る。

## 先送りした話を回収する

「後の節で扱う」「詳しくは後述」と書いたら、その節が実際にその話を扱っているかを確かめる。回収されない予告は、読み手に答えがあると思わせたまま終わる。

中心になる語は、初出で定義と適用範囲を書いてから使う。規則は [naming.md](naming.md) にある。章をまたいで同じ語を使い続けることは、[SKILL.md](../SKILL.md) の「語をそろえる」が決める。
