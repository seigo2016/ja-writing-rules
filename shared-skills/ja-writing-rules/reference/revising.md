# 人が書いた文書を直す

推敲、校正、「読みやすくして」と頼まれたときに適用する。論文の草稿にも適用する。

直す人は、書き手が確かめたことを確かめ直せない。だから、読みやすさのために書き手の主張を動かさない。新しく書くときの規則は SKILL.md の共通ルールにある。ここに書くのは、直すときにだけ要る規則である。

## 直すときに変えないもの

### 確信の度合い

推量を断定にしない。断定を推量にもしない。「〜と考えられる」を「〜である」に、「〜である」を「〜の可能性がある」に書き換えると、書き手が確かめた範囲が変わる。

推量の言い方が読みにくいだけなら、度合いを保ったまま言い方を直す。度合いそのものが誤っていると思うなら、直さずに書き手に伝える。

### 数と枠

元にない枠を足さない。「理由は三つある」「次の二点が重要である」は、書き手が三つ、二つと数えたことを示す。元が列挙していないなら、直す人が数えて枠を作らない。

数値は書き換えない。前後で数値が食い違っていても、どちらが正しいかは直す人には分からない。食い違いを書き手に伝える。

### 主張の重さ

意味だけでなく比重も保つ。原文が主に置いた主張を従に下げない。補足を主張に格上げしない。

一般論の注意 (「ただし、状況によって異なる」) や、書き手の見解を足さない。足した文は、書き手が言っていないことを書き手の名で言わせる。

### 構成と書き手の癖

見出しの付け替え、箇条書きと地の文の入れ替え、段落の組み直しは、頼まれたときか、このままでは読み手が取り違えると具体的に言えるときに限って行う。

語り口、敬語の度合い、改行の癖は、読解を妨げない限り残す。書き手の文書を、直す人の文体にそろえない。

## 意味が確定しないときは書き手に問う

主語や係り受けがあいまいで、文の意味が一つに決まらないことがある。そのときは補って書き換えない。原文を残し、何を確かめたいかを問う。

- 原文: 取込処理では重複を避けるため、キーを登録してから書き込む。
- 誤った直し: 取込処理はデータベースに一意キーを登録してから書き込む。キーの登録先を確かめないまま断定している
- よい対応: 原文を残し、「キーはデータベースと処理内の一時的な表のどちらに登録しますか」と問う

[SKILL.md](../SKILL.md) の「起きることを語で書く」で言い直せない語に出会ったときも、同じように問う。

## 直したあとに確かめること

- 直す前になかった事実、数値、固有名詞が入っていないか
- 推量と断定の度合いが、文ごとに元と同じか
- 否定と条件を畳んだ文の真偽が、元と同じか
- 元が主に置いた主張が、直したあとも主になっているか
- 頼まれていない構成の変更をしていないか

検査スクリプトで確かめる手順は `ja-prose` スキルの「検査スクリプトの使い方」にある。
