# ja-prose — 技術文書のリズムと論理密度

論文草稿、設計文書、README、仕様書など人が読む技術文書全般に適用する。
文脈が自然につながり、読み手が一度で論理を追える日本語を書く。

次の規則は `ja-writing-rules` スキルの SKILL.md と `reference/` が決める。ここには書かない。

| 規則 | 正本 |
|---|---|
| 擬人化、直訳の慣用句、話し言葉の動詞を、起きることの語に直す | SKILL.md「起きることを語で書く」 |
| 二重否定と否定を含む条件を、真偽を保って畳む | SKILL.md「否定と条件を畳むときは真偽を保つ」 |
| 文書そのものについて述べる文、飾り、打ち消しを添えた対比、予防線を削る | SKILL.md「中身のない文と語を削る」 |
| 能動態を優先する。動詞を名詞化しない。名詞の連鎖を動詞に開く | SKILL.md の各節 |
| 渡されていない事実・数値を補わない | SKILL.md「確かめていないことを書かない」 |
| 直すときに確信の度合い、数、主張の重さ、構成を変えない。意味が決まらなければ問う | `reference/revising.md` |
| 因果、例の範囲、譲歩、先送りした話を点検する | `reference/argument.md` |
| 強調 (太字) を絞る | `reference/reports.md`「強調を絞る」 |

## 原則

1. 適切な論理密度を保つ (細切れにしない)
   - 一文一義を、文を機械的に割る規則として読まない。数えるのは書いた主張の数である。
   - 前提の範囲、境界条件、否定、帰結が一つの主張に属するなら自然な複文として一文にまとめる。
   - 長い複文が続いた後は、短い文で結論を述べる。ただし、リズムのためだけに短い文を差し込まない。
2. 文の長さと読点は、文の形で決める
   - 読点で区切った部分がそれぞれ別の主張なら、文を分ける。
   - 読点で語を三つ以上並べているなら、箇条書きか表にするか、並べる数を減らす。
   - 読点を打たないと係り受けが取れない文は、修飾する語を修飾される語の近くに移す。
   - 並列の関係がはっきりしているときだけ箇条書きにする。コロン見出しの箇条書きを乱用しない。
3. 機械的な禁止パズルを避ける
   - 「である」の連続や体言止めを避けるために、不自然な接続詞やゆがんだ言い換えを挟まない。疑問形や体言止めを、語尾を散らす手段として入れない。論理の流れに沿って素直に述語を選ぶ。
4. 一度で書く
   - 通常のターンでは、段落の密度を測る、grep で文末を数えるといった自己ループを回さず、最初から良い型で書く。
   - 検査スクリプトは、推敲を頼まれたときと、既存の文書を直すときに使う。下記の「推敲の手順」に従う。

## 具体例 (Before / After)

### 例 1: 細切れの羅列をまとめる
- **Bad**: 本手法は屋外環境を対象とする。ただし夜間は対象外である。また動体が多く存在する環境では誤差が増加する。そのため静的な昼間シーンで評価を行った。
- **Good**: 本手法は屋外の昼間を対象とし、夜間は扱わない。動体が多い環境では誤差が増えるため、評価は静的な昼間のシーンで行った。

### 例 2: 文長と読点を整理する
- **Bad**: 本処理系においては、入力データの検証を厳密に行うため、異常値を検知した際には、即座に例外を送出し、処理を中断して、ログに記録する。
- **Good**: 本処理系は入力データを厳密に検証する。異常値を検知したときは即座に例外を送出して処理を中断し、ログを記録する。

起きることの語への直し方と、意味が決まらないときの問い方の例は、それぞれの正本 (SKILL.md、`reference/revising.md`) にある。

## 推敲の手順

人の文書を直すときは、この順で進める。

1. 直す前に読み、書き手の主張と、その重さの順を控える。
2. `reference/revising.md` の「直すときに変えないもの」を守って直す。論文の草稿と設計文書では、`reference/argument.md` で論証も点検する。論証の欠けは補わずに書き手に伝える。
3. 直したあと、`reference/revising.md` の「直したあとに確かめること」を通す。下記の検査スクリプトで、機械で拾える差も確かめる。

## 検査スクリプトの使い方

直したあとに確かめるときは、このリポジトリの `hooks/ja_lint/revise_check.py` を使う。このスクリプトは、`reference/revising.md` の「直したあとに確かめること」のうち、機械で拾える次のものを並べる。標準ライブラリだけで動き、外と通信しない。

- 直したあとに増えた、または減った数値・英字の語・カタカナの語 (漢数字の「三つ」なども数える)
- 推量の言い方を含む文で、変わったもの
- 否定や条件を含む文で、変わったもの
- 引用と出典で、変わったもの

```bash
python3 <ja-lint>/revise_check.py <直す前> <直したあと>
python3 <ja-lint>/revise_check.py --git <直したあと>
```

`<ja-lint>` は `$JA_WRITING_RULES_HOME/hooks/ja_lint` (既定は `~/.local/share/ja-writing-rules/hooks/ja_lint`) を指す。`--git` を付けると、HEAD の版を直す前として比べる。並んだものは確かめる場所で、直すかどうかは規約に照らして決める。主張の重さと構成の変更は、出力の最後の「手で確かめること」に従って確かめる。
