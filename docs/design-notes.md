# 設計の判断記録

規約を使うだけならこの文書を読む必要はない。「なぜこの資料を使っていないのか」を後から問われたときのための記録である。

## 参考にした資料の範囲

規約の形成に使ったのは Federal Plain Language Guidelines である。本文を確認した。米国政府の著作物であり、パブリックドメインに属する。

W3C COGA と WCAG 2.1 も、規約の初めの版で参考にした。平易な語を使う、新しい語を作らない、珍しい語と略語を説明する、の考え方はそこから来ている。2026-11 に規約の対象を、エンジニアでない読み手への案内文と通知文から、技術文書・研究の記録・論文の草稿に移した。二つは認知や学習に困難を抱える読み手と一般の読み手に向けた資料で、新しい対象と読み手が違うため、参考資料の一覧から外した。考え方は規約の文に残っている。

調査したが使わなかったものが二つある。

### ISO 24495-1:2023

規格本文を取得していない。有償 (CHF 135) で、公開されているのは概要のみである。

条項の内容は二次資料でしか確認できていない。原典を読んでいない規格を参考資料として挙げると、実際より強い由来関係を示すことになる。よって挙げない。

二次資料の記述を根拠に条項を要約することもしない。

### ASD-STE100

著作権上の懸念で外したのではない。Issue 9 は公式サイトから無償で申請取得できる。

外した理由は設計にある。ASD-STE100 は許可語と非許可語の辞書を中核とする。この規約は語彙リストを持たない。日本語の許可語彙を定めず、機械的な適合判定もしない。仕組みが違う。

規約のなかに ASD-STE100 と似た要素はある。一つの対象に一つの語、一つの語を一つの品詞で、といったものである。ただしこれらは用語管理や技術文書の一般的な考え方から独立に導ける。執筆時に ASD-STE100 の本文を参照していない以上、類似だけを理由に出典として挙げない。

## 外部のスキルから採ったものと見送ったもの

文章を直す外部のスキルを六つ参考にした。どれも MIT License か Unlicense で、文を写すことも許されている。それでも規約の文は書き下ろし、例文も作り直した。下の「権利の扱い」と同じ方針である。

- [natural-japanese](https://github.com/coji/natural-japanese): 直すときに足さないものの範囲 (確信の度合い、数の枠、一般論の注意)、起きることの語で書く考え方、打ち消しの分け方、構成を理由なく変えないことを採った。全段落の書き出しと、指摘が収束するまで lint を繰り返す手順は採らなかった。通常のターンでは自己ループを回さない (`ja-prose` の原則 4) 方針と合わないためである。検査スクリプトは、入っていれば使う外部の道具として参照する
- [meiseki](https://github.com/bamboo-nova/meiseki): 二重否定と否定を含む条件を、真偽を保って畳む考え方を採った。textlint と prh の辞書をフックに組み込むことは採らなかった。Node への依存と、警告で作業を止める仕組みが、助言だけを出すフックの設計と合わない。代わりに、二重否定の型だけを `rules.jsonl` に正規表現で足した。文の抜粋を外部の API に送る層も採らなかった
- [japanese-tech-writing (k16shikano)](https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d): 論証の点検 (`reference/argument.md`) と、言い直しで比喩を見分ける二段の確かめ方を採った。書籍の原稿に固有の細則は採らなかった
- [yomiyasu](https://github.com/nanaism/yomiyasu): 文の長さと読点の目安、意味を確かめずに補わない原則の考え方を、以前から参考にしている。直す前と後の差を見るスクリプトは、引き続き参照する
- [skill-deslop](https://github.com/stephenturner/skill-deslop) と [humanizer](https://github.com/jooray/humanizer): 英語の生成文に出る型の考え方を `slop-removal` に採った。型の詳しい一覧と例は転載せず、入っていれば参照する

natural-japanese、meiseki、japanese-tech-writing が持つ、AI らしい日本語の語の一覧は、どれも転載しなかった。この規約は語彙リストを持たないためである。natural-japanese と meiseki の一覧は、どちらも japanese-tech-writing を出典に挙げている。考え方を規約の一か所に書けば足りる。

語彙リストを持たない方針の例外が一つある。`slop-removal` の英語の型の一覧である。英語の生成文に出る語は、英語の文献で既に一覧として整理されており、日本語の規則とは別のものとして扱う。

## 語数の数値を使わない理由

分かりやすさの基準として語数を挙げる資料はある。採用していない。

数値はいずれも英語の語数を前提としており、日本語の字数へ換算できない。対象読者も異なる。読解に困難を抱える利用者に向けた基準と、技術文書の基準を同じ数値で扱えない。

判断は一文一義と、一段落に一つの話題で行う。`ja-prose` にある字数と読点の数は、点検を始める合図であって、判定には使わない。

## 権利の扱い

規約の文はここで書き下ろした。参照した資料の条文を訳していない。語彙リストを転載していない。

このリポジトリは、いかなる規格団体からも認定・承認を受けていない。規格への適合を主張しない。「準拠」ではなく「考え方を参考にした」と書く。

W3C の文書には二つのライセンスがある。WCAG 2.1 は W3C Document License のもとにあり、派生物の公開を制限する。COGA は permissive document license である。いずれも条文を訳して組み込まない方針で扱う。
